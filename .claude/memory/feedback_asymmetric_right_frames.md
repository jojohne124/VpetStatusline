左右配色不對稱的角色（Mastemon 左半天使右半惡魔）不能靠 runtime 鏡射 —— 一鏡射黑白兩半互換，
看起來像換了一隻。要自帶 `_r` 幀：`config.rightOffset = frameCount`，art.json 變 2× 幀，
`getFacingRows()` 就會改讀後半段而不是 `flipRows()`。cut-in 同理，缺 `frames[1]` 我方會被翻轉。

**慣例直接看 G-Greymon**（第一個這樣做的角色）：`_r` = 輪廓**完全**鏡射（逐格差 0）
+ 同位置換色，換的是橘↔鋼灰兩條色階，多對一（`247,154,41` 和 `247,178,41` 都併到 `115,117,132`）。

**流程就三步**（使用者指定，`scripts/gen-mastemon-right.js`）：
1. 建 惡魔色↔天使色 換色表 —— 逐色算 bias=(L-R)/(L+R)，|bias|≥0.7 才是單側專屬色，
   分色系（無彩／水藍↔粉／金髮↔黃綠）後**同色系內按明暗排序**配對
2. 原圖鏡射存成 `x_r`
3. 對 `x_r` 每一點套表

**Why:** 我繞了兩圈才照這個做。第一版判斷「圖包是正面站姿沒有朝向」直接 `cp` 原圖 → 等於沒鏡射；
第二版改「顏色照螢幕位置取原色」→ 方向看起來沒變、還有補色造成的色塊缺失。都被打回。

**踩到的兩個坑：**
- 反向（惡魔→天使）要取該階**像素數最多**的那一色當代表。取第一色會挑到 `69,46,41`(棕,77px)
  而不是 `30,41,46`(暗底,229px)，畫面冒出一堆棕色塊。
- 兩側共用的暗色（`22,17,24` bias -.39、`63,55,67` -.29、`53,53,53` +.65）和膚色／嘴紅**不能進表**，
  一起換會把每半邊自己的明暗打散。cut-in 是 96x48、47 色（17 色不在角色調色盤），用 RGB 最近色沿用配對。

**守門測試**在 `scripts/test-plaza.js` 的「客製右向幀」一節 —— 驗的是專屬色群的平均 x 沒換邊
（容差 2.5，多對一會讓重心位移一格多），不是驗某幾格像素，所以換演算法也不會假紅。
另外 `pixels.json` 手調過（`prepare` 重跑不等於它），所以**不能跑 `char-cli process`**，
只能以 pixels.json 為來源 + `char-cli build`。相關：[[feedback_single_frame_reimport]]、[[feedback_char_source_16x16]]
