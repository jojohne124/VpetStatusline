# 廣場廣播 規格（草案）

> 2026-10-29 草案，**未實作**。使用者還在考慮，定案前不動程式。

## 一、目的

從廣場發一則廣播，**所有開著 daemon 的人都看得到**：

- 在廣場裡：跟聊天一起出現（醒目樣式）。
- 不在廣場（前線、營地、mini 小視窗、桌面小寵物）：跳出泡泡框。

## 二、誰能發

- **dev 限定，只有使用者本人**。比照現有的管理功能（踢人、刪聊天）：
  - 用主機上的管理金鑰 `~/.vpet/plaza-admin.key` 驗身分，伺服器驗，沒金鑰就發不出去。
  - 金鑰只在 plaza-host 那台，不進 repo、不出貨（同既有規定）。
  - 頁面的發送入口放在 dev 區（正式版藏起來；`DEV_ONLY` 擋指令）。
- 之後若要開放給一般玩家，另外定冷卻、字數、管理員刪除、個人關閉等規則（見 §八）。

## 三、連線方式：daemon 開機就掛一條、主機有事才推

現況：不在廣場的 daemon 跟主機之間**沒有常駐連線**，只有每 30 分鐘問一次新版（`/update/manifest`）和天氣（`/weather`）。
廣場的串流（`/events?id=`）要先 `/join` 報到，進廣場才開、離開就關，不能拿來用。

新增一條**廣播串流**：

| | 廣場串流（現有） | 廣播串流（新） |
|---|---|---|
| 什麼時候開 | 點廣場才開 | daemon 開機就開 |
| 要不要報到 | 要（`/join` 拿 id） | 不用 |
| 推什麼 | 名單、移動、聊天… | 只推廣播 |
| 心跳 | 15 秒 | 盡量稀疏（見下） |

- daemon：`GET /bc/stream?since=<最後看到的序號>`（SSE），開了就掛著，不輪詢。
- 主機平常不送任何東西；有廣播才推一則 `event: bc`。
- **閒置連線被中間設備掐掉**（公司防火牆／DLP）：
  1. 先用 TCP keepalive（`socket.setKeepAlive(true, 60s)`），作業系統自己送探測，程式不管。
  2. 實測若仍會被切，再加稀疏心跳（3～5 分鐘一個 SSE 註解行 `:\n`）。
- **斷線重連**：1 分鐘後重連，連不上就逐次拉長，上限 10 分鐘；接上就歸回 1 分鐘。不在公司網路時不會一直白打。
- 開發版／測試起的 daemon（`--isolated`、`VPET_PLAZA_URL` 指到別處）照指定的網址連，不碰真主機。

### 不採用的做法

| 做法 | 不採用的原因 |
|---|---|
| 每 30～60 秒輪詢 `/bc?since=` | 可行且簡單，但使用者希望不要一直問 |
| 掛在新版檢查／天氣上 | 30 分鐘才問一次，太慢 |
| 主機直接連到每台 daemon | daemon 只聽 localhost:3010，要對區網開放＋防火牆，資安不划算 |
| 區網 UDP 廣播 | 公司網路常擋跨網段廣播、Windows 防火牆會跳詢問，不可靠 |

## 四、伺服器（plaza-server）

- `POST /admin/broadcast`：`{ token, text }` → 驗金鑰 → 存一則 `{ seq, text, at, until }` → 推給所有廣播串流＋廣場串流。
- `GET /bc/stream?since=N`：開 SSE；先補送 `seq > N` 且**還沒過期**的，之後即時推。
- 只存記憶體（同聊天），伺服器重開就清空。保留最近 10 則。
- 過期：發出後 **10 分鐘**（`BC_TTL_MS`，待定）。過期的不補送 —— 開機或斷線很久回來不會被舊消息淹沒。
- 字數上限（暫定 100，同聊天）。
- 連線上限：不設硬上限，但記錄目前掛著的數量（log），觀察負擔。

## 五、daemon 與頁面

- daemon 收到廣播 → 存最新幾則＋最後序號 → 經 `/state` 給頁面（頁面不另開連線）。
- 頁面：**不壓黑的泡泡框**，從舞台右上滑進來，停幾秒（暫定 8 秒）自己收；點一下關掉。
  - 位置不蓋住舞台中間（演出規則：對話框在舞台下方；泡泡框屬通知，放舞台角落、不擋操作）—— 定案時確認。
  - 連續幾則：排隊，一次一則。
- 在廣場裡：聊天欄出現一則醒目的「📢 廣播」（不同顏色），同時也跳泡泡框。
- mini 小視窗：頁面本身會顯示。**縮成桌面小寵物時**頁面看不到 → 交給系統匣提醒（見下）。
- 系統匣：已有進化／戰鬥的「提醒」氣泡，廣播也走同一套（選單可開關）。

## 六、相容與上線

- 伺服器加新路由 → **plaza-host 要重開**（需使用者同意）。
- 舊版 daemon 沒有廣播串流 → 不在廣場時收不到；在廣場裡會以聊天的形式看到（若伺服器順便寫進聊天，見 §八）。
- 新版 daemon 遇到舊主機（沒有 `/bc/stream`，回 404）→ 視為不支援，拉長到 10 分鐘才再試，不報錯。

## 七、測試（實作時）

- 伺服器：沒金鑰發不出去；發了廣場內、廣場外都收到；`since` 補送只補未過期的；過期不補；重開清空。
- daemon：開機自動連；斷線重連間隔逐次拉長、接上歸位；收到後 `/state` 帶出去。
- 頁面：泡泡框出現／自動收／點掉；正式版沒有發送入口；`DEV_ONLY` 清單有發送廣播的指令。
- 每條新斷言照慣例做還原驗證（拿掉修正會紅）。

## 八、待決定

1. 過期時間（暫定 10 分鐘）與保留則數（暫定 10）。
2. 泡泡框位置、停留秒數、樣式。
3. 系統匣提醒要不要做、預設開或關。
4. 廣場內是否也寫進聊天紀錄（舊版 daemon 在廣場內就看得到），還是只跳泡泡框。
5. 玩家要不要能關掉「廣播彈窗」（dev 限定時期可以先不做）。
6. 之後是否開放一般玩家發送；若開放，冷卻、字數、刪除、檢舉規則。
