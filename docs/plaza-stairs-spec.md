# 廣場小遊戲：下樓梯

> 狀態：**第一期實作中（2026-10-20）**：單人無限制可以玩（模擬、伺服器迴圈、推播、畫面、排行榜）。
> 第九節三題照建議定案：角色 12 點、階梯照 4.2、先不給獎勵。
> 實作後新增：**開局倒數 2 秒**（這段不捲動；第一版一出發不到 1 秒就被天花板刺到），開局站得低一點，
> 捲動速度 5～13 點/秒（草稿是 7～16，實測太趕）。
> 致敬《小朋友下樓梯》（NS-SHAFT）：畫面一直往上捲，左右移動踩階梯往下走，
> 碰到天花板的尖刺扣血、掉出畫面底部就出局，計分是走了幾層。

## 一、需求（使用者定案）

| # | 項目 | 決定 |
|---|---|---|
| 1 | 入口 | 在廣場裡發起「下樓梯」房間，**上限 4 人**（之後可能放寬） |
| 2 | 等待 | 有等待出發的介面；**房主可以提早出發** |
| 3 | 模式 | **生存制**：剩一人就結束，至少 2 人才能出發。**無限制**：各自玩到死，排行榜記層數，1 人也能玩。**2026-10-20：先不分模式，一律無限制**（選單上不放模式鈕；生存制的程式留著，之後再開） |
| 4 | 碰撞 | 玩家之間左右會**互相推擠**，也可以**踩在別人頭上** |
| 5 | 排行榜 | 存在**廣場主機的檔案**，伺服器重開也還在 |
| 6 | 操作 | 鍵盤 **← →** 或 **A D**（要先點一下畫面取得焦點） |
| 7 | 畫面 | 跟廣場一樣大，**蓋在廣場畫面上**（不換頁） |

## 二、架構：跟平常走路分開的是「誰算位置」，連線本身沿用

平常廣場走路，伺服器**不算位置**：它只發每個人的起點，各台 daemon 用 `plaza-walk.js` 自己算（一拍 750ms）。
下樓梯不能這樣做：玩家會互相推擠、踩頭，四台各算各的一定會分岔。所以：

| 段落 | 平常走路 | 下樓梯 |
|---|---|---|
| 誰算位置 | 每台 daemon 各算 | **廣場伺服器統一算**（每個房間一個遊戲迴圈） |
| 一拍 | 750ms | **50ms（20Hz）** |
| daemon ↔ 伺服器 | 上行 POST、下行 SSE | **同一條 SSE**，多幾種事件（`stairs:*`）；上行多一個端點 |
| 瀏覽器 ↔ daemon | 輪詢 `/plaza`（250ms） | 遊戲中**另開一條 SSE**（`/stairs/stream`），每拍推一次 |
| 畫面 | 每次輪詢重畫 | 60fps，在兩拍之間補間 |

也就是說：**不需要新的連線**（daemon 跟廣場伺服器之間還是那一條），新的是「伺服器上的遊戲迴圈」跟
「瀏覽器到 daemon 的推播」。

### 2.1 為什麼是 50ms

- 下行：每拍把全場狀態推給四個人，一包約 300 bytes → 每人每秒約 6KB，內網沒有負擔。
- 上行：只在按鍵**改變**時送一次（左／右／放開），不是每拍送。
- 手感：內網延遲大多是「等下一拍」，0～50ms。下樓梯是慢節奏遊戲，這個延遲感覺不太到。
- 不再往下壓：HTTP 與瀏覽器端的抖動會比收益大。實測覺得黏再改 33ms（30Hz）。

### 2.2 協定（草稿）

上行（daemon → 伺服器，POST）：

| 端點 | 內容 |
|---|---|
| `/stairs/open` | 發起房間 `{ mode: 'survival' \| 'endless' }` |
| `/stairs/join` `/stairs/leave` | 加入／離開房間 |
| `/stairs/start` | 房主出發（人數不足就拒絕） |
| `/stairs/input` | `{ dir: -1 \| 0 \| 1, seq }`，只在改變時送 |

下行（伺服器 → daemon，既有的 SSE）：

| 事件 | 什麼時候 |
|---|---|
| `stairs:rooms` | 房間清單有變（廣場上所有人都收得到，用來顯示房間） |
| `stairs:lobby` | 房間成員、模式、房主有變（只發給房間裡的人） |
| `stairs:tick` | 遊戲中每 50ms 一次：拍號、捲動高度、階梯、每位玩家（x, y, vx, vy, hp, alive, dir） |
| `stairs:end` | 結束：名次、層數、有沒有破紀錄 |

`stairs:tick` 由 daemon 原樣轉給瀏覽器的 `/stairs/stream`。

## 三、房間與等待

- 廣場上任何人都能發起房間，選模式（生存制／無限制），發起者是房主。
- 廣場上其他人看得到「🪜 下樓梯（2/4）生存制」，點一下加入。
- 等待畫面：成員頭像、模式、「出發」（只有房主能按）、「離開」。
  - 生存制少於 2 人時，出發鈕停用並提示「至少 2 人」。
  - 滿 4 人不會自動出發，等房主按。
- 房主離開：交給最早加入的人當房主；沒有人了就解散。
- 遊戲中不能再加入（等下一局）。
- 在房間裡（等待或遊戲中）的人，在廣場上頭頂顯示 🪜，別人不能邀他對戰。

## 四、玩法

### 4.1 場地

- 跟廣場畫布一樣：**69 × 54 點**，蓋在廣場畫面上。
- 角色**縮成 12 點**（圍爐已經有現成的縮放，`scaleDots`）：16 點的話 4 隻並排就 64 點，69 寬的場地幾乎動不了。
- 天花板一排尖刺；底部是出局線。

### 4.2 階梯（數值都是草稿，實作時調）

| 種類 | 效果 | 出現比例 |
|---|---|---|
| 普通 | 站得住；踩 3 次回一顆心 | 50% |
| 尖刺 | 站得住；踩上去扣一顆心 | 15% |
| 輸送帶（左／右） | 站上去會被帶著走 | 15% |
| 彈簧 | 把人彈起來 | 10% |
| 翻板 | 站上去一下子就翻掉，人往下掉 | 10% |

- 每塊寬 14～20 點，從底部冒出來、往上捲。
- 階梯由伺服器用房間的 seed 產生，大家看到的一樣。
- 越往下捲得越快（每 10 層加速一次，有上限）。

### 4.3 角色

- 用每個人自己**前線的那隻 vpet**，維持原本的像素風。動作：站著用 IDLE、移動中左右換向、受傷閃一下（HURT）、出局用 SAD。
- 血量是**三顆點陣心**（2026-10-20 改：10 格的血條看不出來是什麼）。碰到天花板尖刺扣一顆，並被往下推。
  踩普通階梯不是每次都回：踩 3 次回一顆（每次都回的話扣一顆馬上補回來，太簡單）。
- 掉出畫面底部、或血量歸零就出局。

### 4.4 玩家碰撞

- **左右推擠**：兩隻橫向重疊時，各推開一半。
- **踩頭**：從上面落到別人頭上，就站在他頭上，被踩的人往下壓一點。被踩的人走開，上面的人就往下掉。
- 碰撞由伺服器統一判定。

### 4.5 模式與結束

| 模式 | 結束條件 | 結果 |
|---|---|---|
| 生存制 | 只剩一人（或全滅） | 最後存活的人獲勝；同一拍全滅就比層數 |
| 無限制 | 所有人都出局 | 每人的層數寫進排行榜 |

- 層數 = 這個人踩過的最低那塊階梯是第幾層。
- 結束畫面顯示名次、層數、有沒有破個人紀錄或全服紀錄，然後回到等待畫面（可以再來一局）。

## 五、排行榜

- 存在廣場主機：`~/.vpet/stairs-board.json`。只放名牌、角色、層數、日期，不放其他個人資料。
- 只記**無限制**模式。保留前 50 名，每人只留最好的一筆。
- 廣場上可以開排行榜看（前 10 名＋自己的名次）。
- 跟管理金鑰同一個資料夾，但**不是**秘密檔案；照樣不進 repo、不出貨。

## 六、失敗與邊界

- 遊戲中斷線：超過 3 秒沒接回來就算出局（不能讓一個人的網路卡住整局）。
- 房主斷線：等同離開，房主交給下一個人。
- 伺服器重開：房間全部消失，大家回到廣場（排行榜在檔案裡，不受影響）。
- 版本不同：房間帶協定版本號，版本對不上的人看不到房間（避免進去卡死）。
- 輸入防作弊：伺服器只收 -1／0／1，速度、位置一律伺服器算。
