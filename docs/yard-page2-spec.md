# 營地第二頁 規格（草案）

營地從一頁（4 隻）擴充成兩頁（8 隻）。第二頁接在原本營地的**右邊**，翻頁＝鏡頭往右滑。

狀態：**第一版已做好，但未實裝**（2026-10-15）。開關 `agumon-core.js` 的 `PAGE2_ENABLED = false`：
自然觸發全部關閉，只有 dev 能強制觸發來預覽。Keramon 家族（Keramon → Chrysalimon → Infermon → Diablomon）
美術調整完成後，把開關打開才算實裝。

## 一、解鎖：連續擊倒 Diablomon 與 Armagemon

| 階段 | 觸發 | 結果 |
|---|---|---|
| 一 | **營地滿 4 隻、尚未解鎖**時，自動戰鬥遇到 Diablomon 並打贏 | 記下「第二階段待觸發」（存 `ranch.json`） |
| 二 | 第二階段待觸發中，玩家**進入營地** | 營地特殊表演（**強制非節慶背景**，春節圍爐也蓋過去）→ 玩家從營地挑一隻與 Armagemon 交戰，戰鬥蓋在畫面上（同廣場對戰） |
| 勝 | 打贏 Armagemon | 解鎖第二頁（上限 4 → 8）、營地自動加入一隻全新的 Keramon（下一個空格，通常是第 5 格）、重抽池開放 Keramon（只限這個玩家） |
| 敗 | 輸給 Armagemon | 第二階段作廢，**從打 Diablomon 重來** |

- **誰會遇到 Diablomon**：只有 Ultimate 以上的桌寵（像打大魔王）。現行對手是同階抽、SU 退回 Ultimate 池，
  所以把 Diablomon 放進 Ultimate 的對手池就自然只有這兩階遇得到。機率先比照一般遇敵（池裡平均抽）。
  ⚠️ 條件不成立（營地沒滿 4、已解鎖）時也照常會遇到、照常計勝負，只是不進第二階段。
- **Armagemon 戰力 210**：2026-10-15 起所有 SU 敵人一律 210（見 `power-table.md`）。營地裡的桌寵以
  凍結時的戰力算勝率（Ultimate 封頂 200 → 勝率略低於五五）。
- **營地掉到 4 隻以下**：右鍵選單只在營地裡，但 CLI 的 `vpet release` 與前線的合體進化（會吃掉營地一隻）
  都能在不進營地時減少營地數量。決定：第二階段**照樣保留**，Keramon 補進下一個空格。
- 解鎖後上限 4 → 8。照 `ranch-spec.md` 的規則，上限不吃存檔，所以不復活 `cap` 欄位，
  改記「解鎖了沒」：`ranch.json` 加 `page2At`（解鎖時間戳），`ranchCap()` = 4 + (已解鎖 ? 4 : 0)。
  第二階段待觸發記成 `page2Quest`（打贏 Diablomon 的時間戳）。
- **Keramon 進重抽池**：重抽只從 roster 的 starters 抽，要另外加「這個玩家已解鎖」才放進去（存檔記 `page2At` 即可判斷）。
- 實作時先留判斷入口（`page2Unlocked(ranch)`）與 dev 用的強制解鎖／強制進第二階段。

## 二、分頁

- **照名單順序分頁**：第 1～4 隻在第一頁，第 5～8 隻在第二頁。
- 營地有 **5 隻以上**才出現翻頁鈕（未解鎖時上限 4，自然不會出現）。
- 放生第一頁的某隻、營地剩 ≥4 隻時，後面的會往前遞補（第 5 隻補到第一頁，畫面上瞬移一次）。
  **已確認可以接受**，不做「每隻綁定某一頁」。
- 換出（swap）是原地放回同一格（2026-10-14 起），不會把人換到另一頁。

## 三、畫面

- 營地場地從 52×40 加寬成 **104×40**（兩頁），伺服器照舊組整張；前端只露出一頁寬（416px），
  翻頁時以 CSS 平移鏡頭（滑行）。
- 前線舞台寬度不變（營地與前線同版位切換，寬度一樣頁面才不會跳）。
- 背景：草地是程式畫的，給兩倍寬即可。節日背景逐一檢查 —— 畫在正中央的主物件（例如聖誕樹）
  要決定放在哪一頁／是否兩頁各一個。
- **春節圍爐不翻頁**：圍爐期間全員坐同一桌（座位表本來就會依人數縮小角色，8 隻坐得下），
  不顯示翻頁鈕、鏡頭固定第一頁。

## 四、走動範圍

走路演算法（`plaza-walk` 的 `posAt`）只吃一個矩形範圍，跟場地多寬無關 —— **跨頁走技術上不難**，
範圍畫成跨過兩頁接縫就會跨頁走。真正要多做的是外圍：

| 項目 | 內容 |
|---|---|
| 點擊判定 | 摸摸、長按拎起、右鍵選單的「點到誰」都要加上鏡頭偏移 |
| 拎著跨頁 | 第一版**不行**：拎著時不能翻頁 |
| 範圍編輯器 | `zone-editor` 要能編 104 寬的場地 |
| 切法表 | `YARD_LAYOUTS` 補 5～8 隻（目前只到 4） |

建議（待定案）：第一版**每隻只在自己那頁走**，接縫附近少數幾隻的範圍稍微跨過去，像在兩頁之間串門子。
全部可跨頁的話，看第一頁時常有角色走出畫面，看起來像少了一隻。5～8 隻的範圍另外規劃。

## 五、表演

| 段落 | 畫面 | 操作 |
|---|---|---|
| 第一階段提示 | 前線，壓黑 + 老師 CutIn + 漫畫式對話框（逐字打） | 點一下打完／關閉；只跳一次（`page2Quest.seen`） |
| 對峙 | 營地強制非節慶背景；我方站左側面向右（ANGRY）、Armagemon 站右側面向左（待機兩幀） | 老師兩句 → 選一隻 |
| 選一隻 | 不壓黑，對話框「選一隻夥伴出戰」＋〔放棄〕；滑過去亮黃色虛線框 | 點 → 確認「派 ○○ 出戰？」〔出戰〕〔再想想〕；摸摸／拎起／右鍵在事件中停用 |
| 戰鬥 | 蓋在營地上（同廣場對戰的 battlebox） | 勝負開打時決定；中途離開照結果處理 |
| 贏 | 老師 → 鏡頭往右滑到第二頁 → Keramon 從上方空降（落地彈一下＋揚灰）→ 老師 | — |
| 輸／放棄 | 老師講完 → Armagemon 往右退場（約 4 拍）→ 營地回平常 | 放棄先確認一次 |

台詞只寫在 `src/daemon/page2-talk.js`（`{name}` = 派出去那隻）。

## 六、實作

- **進度全在 `ranch.json`**：`page2Quest`（待觸發，`seen`）→ `page2Fight`（派誰、勝負、開打拍）→
  `page2Result`（結果；輸的 `exitStep` = 開始退場）；解鎖記 `page2At`。前端只負責演，
  每次 `/yard` 先 `page2Settle` 結算，所以關掉分頁、重新整理都能接著演。
- **分頁**：伺服器每次只合成一頁（`/yard?pg=1`），每頁就是一個 ≤4 隻的營地（`plaza.yardPages`），
  走路／分區／摸摸／拎起來全部沿用。換頁的滑行在前端：拿兩頁的畫面並排平移。
- **空降**：`/yard?drop=<id>` → 伺服器先不畫那隻、回傳牠的兩幀與落點，前端畫往下掉，落地後交回伺服器。
- **指令**（`/cmd`）：`page2Seen`、`page2Fight {which}`、`page2GiveUp`、`page2Ack`；
  dev：`page2Dev {act: quest | win | lose | unlock | reset}`（`DEV_ONLY`，release 擋掉）。
  營地的 dev 列有「第二頁」下拉。
- **測試**：`test-yard-page2`（隔離 daemon 走完整流程，快轉戰鬥）、`test-ranch`（核心）、
  `test-plaza`（分頁、對峙）、`test-daemon-page`（台詞、pollYard 的 else 不能被插斷）。
- 實裝時要做：開關改 true；Keramon 家族進 roster 與否另議（見待辦）。
